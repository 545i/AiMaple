# 角色運動校準報告（第一輪）

日期：2026-07-24　方法：`server/calib.py`（Arduino 實體按鍵 → 小地圖黃點位移，~10Hz 軌跡取樣）
單位：小地圖像素（px）。測試視窗 2560×1440、小地圖畫布 330×168。
原始資料：`server/calib_data.jsonl`（每筆含完整 trace 時間序列）。

## 1. 左右移動：按住時長 → 距離

| hold(s) | \|dx\| (px) |
|--------:|--------:|
| 0.05 | 0（不動）|
| 0.08 | 3 |
| 0.10 | 4 |
| 0.12 | 6 |
| 0.18 | 8 |
| 0.25 | 9 |
| 0.35 | 11 |
| 0.50 | 16 |
| 0.70 | 22 |
| 1.00 | 32 |
| 1.40 | 42 |

**模型**：`|dx| ≈ 30.6 × hold + ~1`（px，hold ≥ 0.08s 時高度線性；左右完全對稱，dy=0）
- **最短有效按鍵 ≈ 0.06–0.08s**；0.05s 以下遊戲不反應
- 位移已含放開後的慣性滑行（trace 顯示滑行 ≤ 2px）
- 走速 ≈ **30.6 px/s**（小地圖座標系）

## 2. 跳躍（X）

- **單跳（不按方向）**：峰值上升 **14px**，水平位移 0，全程約 0.6s（trace: 61→47→57）
- **單跳＋按住方向**：|dx| ≈ **20px**

## 3. 二段跳（X→間隔→X）＋按住方向

| interval(s) | 觸發情形 (右/左) | \|dx\| 平均 | peak 平均 |
|------------:|:---:|---:|---:|
| 0.05 | ✗ / ✗ | 20 | 15 |
| 0.08 | ✗ / ✓ | 45 | 15 |
| 0.10 | ✗ / ✓ | 40 | 14 |
| 0.13 | ✓ / ✗ | 41 | 15 |
| 0.16 | ✓ / ✓ | 60 | 17 |
| 0.20 | ✗ / ✓ | 36 | 17 |
| 0.25 | ✓ / ✓ | **71** | 22 |
| 0.30 | ✗ / ✗ | 21 | 14 |
| 0.40 | ✗ / ✗ | 20 | 14 |
| 0.50 | ✗ / ✗ | 26 | 14 |

判定：|dx| ≥ 45 ≈ 有觸發二段跳；~20 = 只有單跳（含方向）。

**結論**：
- **觸發窗**：約 **0.08 ~ 0.28s**。0.05s 必不觸發（太快，印證使用者說法）；≥0.30s 必不觸發（窗已過）
- **穩定觸發區：0.16 ~ 0.25s**（兩方向皆成功）；窗邊緣(0.08/0.10/0.13/0.20)成敗參半
- **距離隨間隔增加**：0.16s→~60px、0.25s→~71-78px（越晚按第二下飛越遠，印證使用者說法）
- 邊緣不穩定的原因：整條鏈路有 ~20ms 級抖動（韌體 tap 內建 20ms 按住 + 序列埠傳輸 + 遊戲 60fps 輸入取樣），間隔落在窗邊緣時被抖動翻轉

## 待補（下一輪，使用者指示明天繼續）

- **地形判別（使用者指出的關鍵）**：本輪部分樣本 dy≠0（落在高/低平台），會改變二段跳
  的實際水平距離——需先從小地圖/軌跡分辨「平地 vs 高低起伏」，分地形分別建模：
  - 平地上的二段跳距離基準
  - 落點高於/低於起跳點時的距離修正
- 每個 interval 重複 n≥6 次 → 觸發機率曲線（目前 n=2，窗邊緣需更多樣本）
- 下跳（下+X）、爬繩、慣性補償、空中轉向
- 不同地圖的 px↔遊戲座標比例（小地圖是等比縮放，各地圖比例不同）
