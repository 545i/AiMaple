# 符文箭頭判讀:用 CNN 取代色度分割

2026-08-15

## 問題

`dataset_eval` 在 367 筆資料集上的總分是全對 140/365、單支 597/1460(41%)。
這個數字看起來像「判向不準」,但拆開來完全不是:

| 環節 | 實測 |
|---|---|
| 膠囊定位 | 被擋下 212 筆,其中 199 筆的框全都是 329×81,p5=p50=p95 —— **零誤差** |
| 找不到膠囊 | 剩下的 13 筆 |
| 判向(模板比對) | 分割乾淨時單支 597/612 = **97.5%**,全對 140/153 = 91.5% |
| 色度分割 `_chroma_map`/`_seg` | **199 筆卡在面積閘門** |

把被擋下那 199 筆強行放行(`strict=False`),單支只剩 253/428 = 59.1%、全對 21/107 =
19.6%。所以閘門擋得有道理 —— 那些樣本的分割是真的壞掉,不是閘門太嚴。

壞在哪裡有數字佐證:被擋下樣本的四格面積 p50 是 1180(期望 250~650)、格間比值 p50
是 3.4(閘門上限 2.0)。就是箭頭被怪物、技能特效、地形疊到時,色度距離把背景一起
吃進去。

**結論:要換掉的是分割,不是判向器。** 判向器在乾淨輸入上已經 97.5%,再訓一個更好的
判向器沒有意義;真正的破口是「怎麼從雜訊裡把箭頭剝出來」,而這正是學習式方法擅長、
手寫幾何規則不擅長的事。

### 為什麼現在做

資料條件出奇地好,而且是可遇不可求的組合:

- 標籤來自**遊戲驗證**(341 筆 `purple_gone`,按完四個方向後紫標消失),不是人工猜的。
- 膠囊框零誤差,裁出來的每格小圖不會跟標籤對不上 —— 這是訓練資料最容易出錯的地方。
- 1408 支可用箭頭(352 筆 × 4),其中 **796 支正是現行流程會失敗的困難樣本**。
- 四個方向互為 rot90,增強的標籤變換是精確的,不是近似。

## 範圍

**做**:每幀、每格的箭頭方向判讀器,取代色度分割。

**不做(本輪)**:旋轉箭頭。遊戲新增了「箭頭持續旋轉、在上下左右其中一個方向停頓約
0.5 秒」的符文,這需要時間軸停留分析與全新的序列資料,使用者要求等取樣條件齊備再開。
它與本設計正交:本設計改善的是「單幀單格判讀」,旋轉問題是「該取哪一幀」。

## 方案選擇

執行期用 **onnxruntime**(使用者指定)。訓練用 PyTorch 離線做完,`torch.onnx.export`
匯出,訓練環境與執行期完全脫鉤。

評估過但未採用:
- **numpy 手寫前向 + `.npz` 權重** —— 零新增執行期依賴,但推論程式碼要自己維護。
- **不學習的整格模板匹配** —— 零成本,但破口正是遮擋與背景雜訊,NCC 對這兩者最沒
  抵抗力。**仍會實作來當基準數字**(見驗收條件),讓模型必須贏得夠多才值得帶依賴。

## 設計

### 資料萃取

逐筆讀 `rune_dataset/index.jsonl`:

1. `capsule` 欄位有框就直接用;是 null 就呼叫 `rune_cv.find_capsule()` 重算;仍失敗
   則跳過(實測 13 筆)。
2. 框四等分(與 `read_dirs` 同一套算法:`w = cap.shape[1] / 4`,第 k 格是
   `[k*w, (k+1)*w)`),裁出每格約 82×81 的小圖。
3. 標籤取 `dirs[k]`。`negative: true` 的樣本不走這條路(它們沒有膠囊)。

不落地中間檔,訓練腳本即時做。但要提供 `--dump <dir>` 把裁切結果連同標籤寫出來,
供人工抽查 —— 裁切對不對是整件事的地基,必須能用眼睛驗。

### 負樣本

現行資料集只有 2 筆負樣本,不足以讓信心度門檻有鑑別力。從同一批圖的**膠囊框以外**
區域裁同尺寸(82×81)區塊,當第 5 類 `none`,數量配到與四個方向類別相當。

這樣「這真的是箭頭嗎」就由模型自己回答,不需要另外維護一套啟發式閘門。

### 模型

- 輸入 32×32×3。膠囊格約 82×81 接近正方形,縮到 32×32 保留形狀資訊。
- 三層 conv(16 / 32 / 64,3×3,各接 BN + ReLU + MaxPool)→ GAP → FC(64→5)。
- 約 25K 參數,ONNX 檔約 100KB,與現有的 `rune_arrow_tpl.png` 同一個量級。
- 輸出 5 類:`up` / `right` / `down` / `left` / `none`。

**輸入用 RGB 三通道,但訓練時強制色相抖動。** 專案早期實測過箭頭顏色是循環動畫
(橘頭綠尾 / 純綠 / 彩虹 / 紫),寫死顏色規則會壞。三通道讓模型有色度資訊可以把箭頭
從背景剝離,大幅色相抖動則逼它學形狀而不是記顏色。

### 增強

| 增強 | 理由 |
|---|---|
| rot90 ×4 | 標籤變換精確(up→right→down→left,`none` 不變),不是近似增強。1408 → 5632 支,四類天然完全平衡 |
| 色相抖動 | 對抗顏色循環動畫,見上 |
| cutout 隨機遮擋 | **最對症的一項** —— 直接模擬怪物與技能特效壓在箭頭上,那正是現行分割崩掉的情境 |
| ±3px 平移 | 模擬膠囊框微幅偏移 |
| 亮度 / 對比抖動 | WGC 擷取偏暗、螢幕截圖較亮,兩種來源都要吃 |

### 訓練 / 驗證切分

**按 `ts` 排序取後 20% 當驗證集,不隨機切。** 同一顆符文、同一張地圖、相近時間的樣本
背景高度相關,隨機切會讓相關樣本跨越訓練/驗證邊界,把分數灌到虛高。

驗證結果要**分兩組報**:
- 「原本就過閘門」那組(153 筆)—— 要求不退步。
- 「原本被閘門擋下」那組(199 筆)—— 這才是要贏的地方。

### 上線整合

新增 `server/rune_nn.py`,負責模型載入、預處理、四格批次推論,回 `(dirs, probs)`。

`rune_cv.read_dirs()` 改成:

```
定位膠囊(不變)
  → 四等分(不變)
  → 模型判向 + 信心度守門
  → 模型檔不在 → 整條退回現行色度分割路徑
```

**守門條件取代現行面積閘門**:四格都不是 `none`,且最低信心度 ≥ 門檻。門檻用驗證集
調到誤判率趨近零的那一側 —— 誤判的代價不是漏一次,而是拿雜訊當箭頭去按方向鍵、
白燒一次符文冷卻,寧可退線給 2 線。

`strict` 參數語意維持不變(預覽用 `strict=False` 才看得到抓到什麼以便診斷)。

**模型檔不存在時必須完整退回現行路徑** —— 沒帶模型的舊 exe 不能壞。

## 驗收條件

用現成的 `dataset_eval()`,拆兩組報:

1. 整體單支正確率 **≥ 90%**(現況 41%)。
2. 「原本就過閘門」那組不得退步,維持 **≥ 97%**。
3. 負樣本**零誤報**。
4. 必須明顯贏過「不學習的整格模板匹配」基準,否則不值得帶 onnxruntime 依賴。

**任何一條不過就不上線**,`read_dirs` 保持走現行色度分割路徑。

## 已知風險

- **1408 支是小資料集。** 增強後名目 5632,但底層只有 352 個不同背景。過擬合風險真實
  存在,靠時間切分的驗證集來抓 —— 如果驗證分數與訓練分數差距大,增強要再加重。
- **困難樣本的標籤是整組驗證的。** `purple_gone` 證明四支**合起來**是對的,不是逐支
  獨立驗證。理論上不存在「四支按對了但其中一支標籤錯」的情況(按錯任一支就解不開),
  所以這個標籤是可信的,但值得在抽查時留意。
- **負樣本是合成的。** 膠囊框以外的區塊未必涵蓋真正的誤判情境(例如公告橫幅、平台
  草皮這些已知干擾源)。若上線後出現誤判,要把真實誤判幀補進負樣本重訓。
